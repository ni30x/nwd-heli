## Fix: Gaps, Session Splitting, Suggestion Recording

### Issues
1. **Gaps** — padding still too large between header/tabs/filter/sessions in both modes
2. **Same text splits into multiple sessions** — `onFinishInputView` fires when keyboard briefly hides (e.g. on back press, suggestions popup), setting `mKeyboardWasClosedAndReopened=true`, which forces a new session even in same field
3. **Suggestions/autocorrect not recorded** — `commitCorrection` and `commitCompletion` in RichInputConnection don't call `recordTypingHistory`
4. **Clipboard paste not recorded** — `setComposingText` path doesn't trigger recording

### Changes

#### 1. `TypingHistoryViewerScreen.kt` — gap reduction
- Section switcher: `vertical = 2.dp` → `vertical = 0.dp`
- Filter chips: `vertical = 2.dp` → `vertical = 0.dp`
- Remove `Spacer(modifier = Modifier.height(8.dp))` before content area
- Calendar mode: reduce internal padding from `horizontal = 16.dp` to `horizontal = 12.dp`

#### 2. `TypingHistoryRecorder.kt` — fix session splitting
The problem: `onFinishInputView` sets `mKeyboardWasClosedAndReopened = true`. Next `onStartInputView` sees this flag and starts a new session, splitting continuous typing.

Fix: Only honor `mKeyboardWasClosedAndReopened` if the keyboard was actually closed for > 2 seconds (real close, not a brief hide for suggestions/popups). Add a timestamp check.

#### 3. `RichInputConnection.java` — add recording to all commit paths
- `commitCorrection` → call `recordTypingHistory(text)`
- `commitCompletion` → call `recordTypingHistory(text)`
- `setComposingText` → call `recordTypingHistory(text)` (for inline suggestions)
